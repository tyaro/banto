## 3. 破ってはいけない不変条件（[conventions.md](conventions.md) 全文が正）

V2 でも下記は不変。詳細と機械検査状況は conventions.md を参照。

- **REST / Tauri 両経路対称**（[ADR-0001](adr/0001-rest-tauri-two-path-symmetry.md)。
  `verify:architecture` rule 8 で機械検査。mutating 操作を片経路だけに足さない）。
- **サービス層非依存**（UI 非依存のヘッドレス層。権限判定・監査はサービス層の
  チョークポイント）。
- **依存を足さない**（[ADR-0002](adr/0002-minimal-dependencies.md)。i18n②で
  ライブラリ検討時はここと衝突しないか必ず判断）。
- **逆依存禁止**（`@banto/*` パッケージはアプリを知らない）。
- **セキュリティ不変条件**（conventions §6。`verify:architecture` rule 9 で一部機械検査）。
- **トークンのみ**（認証はトークン経由。資格情報は OS キーリング等、設定 DB に平文で持たない）。

## 4. 検証（サンドボックスで可能な範囲）

```bash
pnpm check      # フロント型チェック・lint・format
cargo test      # Rust ユニット/結合テスト
pnpm e2e        # Playwright スモーク E2E
cargo audit     # 依存監査
```

- **`src-tauri` はサンドボックス（Linux, webkit2gtk 不在）ではコンパイル不可** →
  コードレビュー + `tauri-check.yml`（`cargo check`）+ 静的検査（`verify:architecture`）で
  担保。**実機 Windows がある環境では `tauri build` で実ビルド/スモーク可**。
- **リリース時**: `node scripts/check-versions.mjs`（全マニフェスト version 整合）、
  タグ時は `--tag vX.Y.Z` でタグ名照合（CR-7）。
- visual regression のベースラインは **Linux 生成のみ**（作業機に WSL/Docker 無し。
  `visual-baselines.yml` を dispatch して CI で再生成する運用）。

## 5. ブランチ / PR 運用

- **このブランチ（eval）＝計画ハブ**。計画・引き継ぎドキュメントはここに置く
  （main には出さない）。V2 の設計更新・本書の更新もこのブランチへ。
- **コードの変更は main から独立ブランチを切って PR**（`claude/<slug>`）。
- **自作 PR のセルフマージは不可**。PR 作成 + CI 緑確認まで行い、**オーナー承認を
  待つ**。マージ後、必要なら eval ブランチへ main を取り込んで同期する。
- **リリース手順**（[remaining-work §3](remaining-work-2026-07-23.md) がテンプレ）:
  CHANGELOG `[Unreleased]` 整理 → マニフェスト bump（`check-versions` 正準集合）→
  CHANGELOG に新版節 → PR → マージ後 `vX.Y.Z` タグ（先に作成・push）→ CR-7 タグ照合 →
  `gh release create`。
