# ADR-0038: モーダルな層の外側は、`layering.ts` の 1 か所が `inert` にする

> English: [0038-modal-backdrop-inert.en.md](0038-modal-backdrop-inert.en.md)

- 状態: Accepted
- 日付: 2026-11-28（オーナー決定: 背景の管理を 1 か所にまとめる・重ねたペインを真のモーダルにする・ペインに「閉じる」を置く）
- 関連: Issue #1055（#1045・PR #1050 で見送った分）/ [ADR-0018](0018-shared-ui-package.md) §10 /
  `packages/ui/src/layering.ts`（層の約束 8）

## コンテキスト

`@banto/ui` のモーダルな層（`Modal`・`Drawer`・`ConfirmDialog`・`CommandPalette`）は `aria-modal="true"` を名乗り、
フォーカスを閉じ込める（層の約束 4）。外側の操作は、画面を覆うスクリムが受けて止めていた。

`ThreePaneLayout` の幅が狭いときに重ねて開くペインは、枠（`.three-pane`）の中しか覆わない。枠の外（アプリのヘッダーなど）は
クリックできる。ここに `aria-modal="true"` だけを付けると、支援技術からはヘッダーが見えないのに、クリックは通る（範囲が食い違う）。

PR #1050 では、ペインを開いた時点で外側の兄弟を `inert` にする `inertOutside` を試して見送った。レビューで残った問題:

- 開いた時点の兄弟を 1 度だけ調べるので、空のポータルが `inert` になり、後からそこに開く上の層まで止まる。
- 知らせの要素（`role="status"` など）を丸ごと除くと、その中のボタン（接続の「再試行」）が背後で押せる。
- 層ごとに自分の周りを `inert` にすると、閉じる順が入れ子でないときに、ほかの層の `inert` を外してしまう。

## 決定

### 1. 文書ごとに 1 つ、「いちばん上のモーダルな層」を `layering.ts` が持つ

モーダルな層は、開いている間 `trackModalLayer(layer)` を呼ぶ（`Modal`・`Drawer`・`ConfirmDialog`・`CommandPalette`・
`ThreePaneLayout` のモーダルの引き出し）。登録された層のうち、いちばん上の 1 つが背景を決める: `<body>` からその層までの
道の、横にある要素をすべて `inert` にする。下の層は、上の層が閉じるまで背景の一部になる。層を閉じる順は問わない
（閉じるたびに作り直す）。

**登録された層どうしの上下**は、次の順で決める。

1. ほかの層の中にあれば、それより上。
2. z-index が違えば、数値の大きいほうが上（開いた順は問わない。1000 のコマンドパレットは、後から開いた 900 の `Modal` より上のまま。
   画面に上に描かれているものが上）。
3. z-index が同じなら、**後から登録した（開いた）ほうが上**。文書の順ではない。レイアウト側のダイアログ（セッション切れの確認など）は
   DOM でページの `Drawer` より前にあることがあり、文書の順で決めると、後から開いたのに `Drawer` の背景として `inert` のままになる。

登録は「開いた」1 回分。閉じて開き直した層は登録し直すので、同じ z-index の中でいちばん上になる（下にあった層が開き直した
ときも同じ。「いま開いたものが上」で一貫させる）。残った層どうしの順は、どの層が閉じても変わらない。

Esc とフォーカスの引き戻しの「手前」の判定（`hasVisibleLayerAbove` など）も同じ規則を使う: 同じ z-index で、両方が登録された層
（またはその中の層）なら登録の順、**どちらかが登録されていなければ今までどおり文書の順**。これで Esc は上の層だけを閉じ、
背景の `inert` と食い違わない。

同じ z-index は CSS では文書の順に描かれるので、判定だけ変えると、上の層が下の層のスクリムの下に描かれる。`OverlayPanel`
（`Modal`・`Drawer`・`ConfirmDialog`。みな `--banto-z-modal`）は、登録のあと、同じ z-index で先に開いている層があれば、その分だけ
自分の z-index を上げる（`--overlay-lift`。1 つだけ開いているときは 0 = テーマの値のまま）。上げたあとは 2 の規則でも同じ答えになる。
アプリ自作の層を @banto/ui の層と同じ z-index で登録するときは、描画の順はアプリが決める（別の z-index にするのが簡単）。

層ごとに `inert` を付け外しする案（参照カウント）は採らない。「いま `inert` であるべき要素の集合」を毎回求めて、付けた分との
差だけを書くほうが、順不同の閉じ・途中の DOM の変化に対して状態が 1 つで済む。

### 2. 外すのは、自分が付けた `inert` だけ

- 元から `inert` の要素には触らない。
- 層が開いている間にアプリが同じ要素の `inert` を書いたら（モーダルを開いたままサイドバーがオフキャンバスに変わる、など）、
  その要素はアプリのものとして手放す（閉じても外さない）。アプリが外したら付け直し、閉じるときに外す。
  書き込みは `MutationObserver` の記録で知る。

### 3. 背景に入れないもの

- **`data-modal-exempt`**（`MODAL_EXEMPT_ATTR`）: どのモーダルよりも上に描かれ、開いている間も使うもの。
  `@banto/touch-keys-svelte` のキー（モーダルの中の欄に打つ。入力欄からフォーカスを奪わない別扱い）。
  `ToastHost` は付けない: `attachFocusTrap()` が Tab をモーダルの中へ戻すので、トーストのボタンはキーボードでは届かず、
  ポインターだけ押せると非対称になる。トーストも下の「知らせの要素」と同じ扱い（文は読まれ、ボタンはモーダルの間 `inert`）。
- **知らせの要素**（`aria-live`（off 以外）・`role="status" | "alert" | "log"`・`<output>`）: `inert` は読み上げも止めるので、
  知らせの要素とその祖先は `inert` にしない。代わりに、**その中の操作部（ボタン・リンクなど）を 1 つずつ `inert` にする**。
  知らせは読まれ、背後のボタンは押せない。知らせの中に操作部を置かないのが本筋（#1055 の並行の修正）で、これは残ったものへの守り。
- **登録されていない、上にある層**（アプリ自作のダイアログ、開いているオフキャンバスのサイドバーなど。既存の「手前」の規則 =
  z-index、同じなら文書の順で判定。登録の順は、登録されていない層には無い）: Esc はすでにそれに譲っているので、操作もできるようにする。自分の付けた `inert` の中に後から現れても見つけて外す。
  ただし、その層が外側を `inert` にはしない。アプリ自作のモーダルな層は `trackModalLayer` を呼ぶ。

### 4. 層が開いている間は DOM の変化に追従する

`MutationObserver`（`<body>` 以下の子の増減と、`inert`・`role`・`aria-live`・`aria-modal`・`hidden`・`class`・`style` など）で
作り直す。後から現れたバナーやポータルの中身も背景に入る。いちばん上の層の中だけの変化では作り直さない。層が無い間は監視しない。

開いた時点の 1 回だけで決める案は、PR #1050 の 1 つ目の問題（後から現れる要素）を解けないので採らない。

### 5. `ThreePaneLayout` の重ねたペインは真のモーダルにする

モーダルの引き出し（既定）が開いている間、ペインは `role="dialog"`・`aria-modal="true"`（名前はペインの名前）になり、
`trackModalLayer` で外側（枠の中央・帯と、枠の外のアプリ）を `inert` にする。スクリムはペインの兄弟なので、`backdrop` で
名指しして背景から外す（クリックで閉じる）。ペインの上端に「閉じる」✕ を置く（`Drawer` と同じ `IconButton`・文言は
`overlayClose`）。中にフォーカスできる要素が無いペインでも、Esc 以外で閉じられる。非モーダルの引き出し
（`leftDrawerModal` / `rightDrawerModal` を false）は変えない。

## 帰結

- `aria-modal` が支援技術から隠す範囲と、クリック・Tab が届かない範囲が一致する。
- `Modal`・`Drawer`・`CommandPalette` の外側も `inert` になる（これまではスクリムとフォーカスの閉じ込めだけ）。スクリムの外に
  はみ出して押せていたもの（スクリムより上の z-index の要素）は押せなくなる。開いている間も使うものには `data-modal-exempt` を付ける。
- `PickerDialog`（日付の選択。`popover` の中の `aria-modal`）は登録しない。入力欄のすぐ横に出る軽い層で、外側の押下で
  閉じる動きを保つ。
- スクリムは今までどおり枠の中だけを覆う。枠の外は、暗くならないが操作できない。
- 「手前」の判定は z-index の数値の比較なので、別のスタッキングコンテキストの中の数値（`ThreePaneLayout` のペインは枠の中の
  `z-index: 2`）と比べると、実際の重なりと食い違うことがある（既存の Esc の規則と同じ限界）。登録されていない層がこれで
  「上」と判定されると、背景に入らない。
- `Modal`・`Drawer` を 2 つ以上重ねている間、後から開いたほうの z-index は `--banto-z-modal` より 1 ずつ大きい。同じ値に置いた
  登録されていない層（開いているオフキャンバスのサイドバー = `--banto-z-sidebar` など）は、文書の順にかかわらずその下になり、
  背景に入る。
- 知らせの要素の中の操作部を `inert` にすると、閉じたときにその操作部が支援技術の木に戻る。`aria-atomic` の知らせでは
  読み直されることがある。
- Shadow DOM の中の層は、shadow root の外側だけが背景になる（中の兄弟は調べない）。
