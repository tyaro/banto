# ADR-0022: 設定カテゴリは下線型ナビゲーション、入力は移動型ラベルと下線を使う

> English: [0022-settings-controls.en.md](0022-settings-controls.en.md)

- 状態: Accepted
- 日付: 2026-11-03
- 関連: [Issue #495](https://github.com/tyaro/banto/issues/495) /
  [conventions.md](../conventions.md) §3・§9・§13 /
  [choiapp-feedback-2026-09.md](../reviews/choiapp-feedback-2026-09.md) §3.2

## コンテキスト

設定画面のカテゴリと選択入力はそれぞれ枠を持ち、ヘッダーと内容にも同じページタイトルが表示されていた。
設定画面で試した下線型の表示について、オーナーが正式採用を了承した。
同日、設定画面のテキスト系入力と選択入力のラベルも移動型にすることを決めた。
既存の Svelte 5、テーマ、ページ遷移、標準の選択操作を活かして囲いを減らす。

## 決定

- 設定カテゴリは横並びの下線型ナビゲーションとする。狭い幅では折り返し、選択中のリンクだけに下線を付ける。
  各カテゴリは独立したページなので、`nav`、リンク、`aria-current="page"` を維持する。
- 設定画面のテキスト・パスワード・数値入力と選択入力は、薄い背景と下線、移動型ラベルを使う。
  空の入力ではラベルを欄内に置き、フォーカス中・値があるときは値の上に移す。
  既存値や自動入力でもラベルが値に重ならないようにする。`label` とネイティブの入力要素を維持する。
- 選択入力はネイティブ `select` を維持する。既存値がある場合はラベルを上に置き、
  空の選択肢では欄内に置く。矢印とポップアップはブラウザ／OS に任せる。
- フォーカスは実線のアウトライン、無効状態は既存の減光と破線の下線で示す。
  強制色では未選択リンクの境界線を取り除き、選択中の下線を識別できるようにする。
- ページタイトルはシェルのヘッダーに表示する。設定の内容側には読み上げ用の `h1` を残し、
  見た目は説明文とカテゴリナビゲーションから始める。
- 実装は設定の `+layout.svelte` と、`.settings-page` に限定した `settings.css` に置く。
  色・寸法は既存のテーマトークンを使い、新しいライブラリ・フォント・画像を取り込まない。

## 検討した代替案

- **枠付きの丸いカテゴリボタンを維持する:** 囲いが多く、設定項目の選択部品とも似る。
  ページの現在地を下線で示す構成のほうが、内容との階層を整理できるため採用しない。
- **浮動ラベルを全フォームの標準にする:** 長い日本語、自動入力、空値、エラーとの組み合わせが増える。
  設定画面だけで状態を確認してから共通部品への展開を判断する。
- **独自のコンボボックスや外部 UI ライブラリに置き換える:** 今回の選択肢はネイティブ `select` で足りる。
  検索や自由入力を必要としない段階で、ポップアップ、フォーカス、支援技術対応の保守を増やさない。
  Carbon・shadcn/ui・CodePen は検討の参考であり、コード・SVG・フォント等はコピーしない。

## 帰結

- 正式採用の範囲は設定画面のカテゴリと入力群に限る。`packages/forms` の入力群、
  `packages/grid-svelte` の表、カード全体、SCADA の運転画面には自動的に適用しない。
  共通部品への展開は、実際の利用箇所と状態を確認して別の変更として進める。
- 保存処理、権限制御、未保存ガード、REST/Tauri の provider 分岐には変更を加えない。
- 継続的な検証では、明暗・標準／ガラス、標準／コンパクト、日本語／英語、狭幅、
  キーボード、フォーカス、無効状態、強制色を確認する。設定画面の画像基準と axe 検査を維持する。
- ネイティブ選択 UI の細部は OS／ブラウザで異なる。Chromium と IPC スタブによる検証を、
  Tauri 実機の WebView・タッチ・読み上げの確認済みとは扱わない。
