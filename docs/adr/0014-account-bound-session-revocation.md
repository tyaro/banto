# ADR-0014: セッションは「アカウントの行 id + 認証の世代」に結び付け、要求ごとに DB で確かめて失効させる

> English: [0014-account-bound-session-revocation.en.md](0014-account-bound-session-revocation.en.md)

- 状態: Accepted
- 日付: 2026-09-24
- 関連: Issue #204 / conventions §1・§6 / roadmap M10・M11 / ADR-0001（両経路対称）/
  ADR-0012（合成 viewer セッション）

## コンテキスト

ユーザーを削除・降格しても、パスワードを変更・リセットしても、既存のセッションが
発行時の権限のまま使い続けられた。REST の `AuthState` はログイン時の `Identity`
（ロール込み）をトークンに保存して期限まで返し、`RoleGuard` はそのロールだけで
認可していた。Tauri の `require_role` もキャッシュした `UserIdentity` で認可して
いた。削除した管理者の古いトークンで、期限内（通常 8 時間、Remember me は 30 日）
なら管理者を作れた。

制約:

- REST と Tauri の**両経路**に効き、片方の経路の変更がもう片方のセッションにも効く。
- 複数のプロセス（Tauri アプリの組み込みサーバ・`banto-serve`・1 つの PostgreSQL を
  共有する複数サーバ）と再起動をまたいで破れない。トークンはプロセスのメモリにしか
  無い。
- `banto-server` はアカウントの保存先を知らない（`UsersService` は注入）。派生アプリは
  自前の `users` テーブル・サービスを持つ。
- 期限の短縮では解けない（失効までの窓が残る）。

## 決定

**セッションは発行時の `SessionStamp { account_id, auth_epoch }` を持ち、認証済みの
要求・コマンドのたびにアカウントを DB から読み直して照合する。** アカウントが
無い・行 id が違う・世代が違えばそのセッションを失効させて 401、一致すれば DB の
**今の**ロールで認可する。

- `users.auth_epoch` は、ロール変更・パスワード変更・パスワードリセットの `UPDATE`
  と**同じ文**で増やす（読んでから書く分割をしない）。削除は行が消えるので不要。
  行 id は再利用されないため、同名で作り直したアカウントは旧セッションを継がない。
- REST: `AuthState::with_session_validator(lookup)` で読み直し関数を差し込み、
  `require_auth`（`AuthState::authenticate`）が照合する。`RoleGuard`・`check`・
  `identity`・`change-password` も同じ照合を通る。
- Tauri: `require_role` が `current_session` で同じ照合をし、キャッシュを
  比較してから書き換える（compare-and-set）。
- ログイン時の世代は資格情報の検証（argon2）より**前**に読む。検証中に確定した
  変更を新しいトークンが生き延びない。
- DB が答えられないときは失効させず、その要求だけ失敗させる（一時的な障害で全員を
  ログアウトさせない・素通りもさせない）。
- 自分のパスワード変更は、変更した当のセッションだけ新しい世代へ付け替えて残す。
  変更の直前に現在のパスワードを示しているため。他の端末・もう一方の経路・
  Remember me のセッションはすべて終わる。間に別の変更が挟まった（世代が 2 以上
  進んだ）場合は付け替えない。

## 検討した代替案

- **案A（採用）: 行 id + 認証の世代を DB に持ち、要求ごとに照合する。**
  利点: 状態が DB にしか無いので、プロセス・経路・再起動をまたいで同じ結果になる。
  降格が即座に効く（ロールも DB から読む）。`banto-server` は読み直し関数を受け
  取るだけで保存先を知らない。欠点: 認証済みの要求ごとに `UNIQUE(username)` の
  索引読み 1 回。LAN の管理画面の負荷では問題にならない。キャッシュは入れない
  （キャッシュの有効期間が、そのまま失効の遅れになる）。
- **案B（不採用）: 失効させたいユーザーのトークンをメモリの一覧から消す。**
  トークンを持っているプロセスでしか効かない。Tauri アプリの組み込みサーバと
  `banto-serve`、複数サーバの間で伝わらず、Tauri のウィンドウのセッション
  （別のトークン空間）にも届かない。トークンを DB に永続化して共有すれば伝わるが、
  トークンの保存・掃除・漏えい面が増え、結局要求ごとに DB を読む。
- **案C（不採用）: 世代を持たず、要求ごとに存在とロールだけを確かめる。**
  削除と降格は防げるが、パスワード変更・リセットで古いセッションが残る
  （漏れたパスワードで得たセッションを切れない）。
- **案D（不採用）: 世代の代わりに「この時刻より前に発行したセッションは無効」を
  持つ。**
  発行時刻と変更時刻をプロセス・サーバ間の時計で比べることになり、時計のずれと
  同じ秒の前後関係で壊れる。単調な整数の世代なら比較が確定する。
- **案E（不採用）: トークンの期限を短くする。**
  窓が短くなるだけで、失効にはならない。

## 帰結

- 派生アプリは `users` に `auth_epoch` を足し、世代を増やす書き込みと、
  `with_session_validator`・Tauri 側の照合を配線する必要がある（CHANGELOG の
  移行手順）。配線しない `AuthState::new` だけの構成は、従来どおり発行時の
  権限を期限まで信じる。
- 照合を差し込んだ `AuthState` では、世代を持たないトークン（`issue_token`）は
  最初の使用で拒否される（fail closed）。アカウントを作ってそのままログインさせる
  経路は `issue_account_token` を使う。
- 同期の `verify`/`identity_for` はメモリだけを見る。アクセスの判断は
  `authenticate`（`require_auth`）を通すこと。`identity_for` は `require_auth` の
  後ろでだけ現在の値を返す（照合のたびに書き戻す）。
- 合成 viewer セッション（ADR-0012）と Tauri のログイン不要モードの合成セッションは
  アカウントを持たないので照合しない。
- SSE（`/api/events`）は接続時に照合する。失効後も、すでに開いている接続は
  切れるまで通知（リソース名と通知文）を受け続ける。
