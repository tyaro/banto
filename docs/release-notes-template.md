# リリース案内の雛形

作成日: 2026-10-01（Issue #221）

リリース（`[Unreleased]` を版節に切り出すとき）に、CHANGELOG の版節の冒頭へ置く案内の雛形。
読み手は派生アプリの作者で、**「タグを上げるだけで済むか」「コピー部分の取り込みが要るか」をこの冒頭だけで
判断できる**ことが目的。読み方・手順は [upgrading.md](upgrading.md)。

使い方: 下の「版節の冒頭」を CHANGELOG の版節にコピーして埋める。該当しない項目は削除せず `なし` と書く
（読み手が「書き忘れ」と「無い」を区別できる）。個々の変更（PR ごとの行）は従来どおり版節の箇条書きに残す。

## 版節の冒頭

```markdown
## [X.Y.Z] - YYYY-MM-DD

**vX.Y.Z — 変更の一行要約。** 版の種類: major（破壊的）/ minor / patch。
派生アプリへの影響: 一文（例: 「依存タグの更新だけで済む」「コピー済みの設定画面の取り込みが必要」）。

| 経路                             | 影響        | 内容                                                                  |
| -------------------------------- | ----------- | --------------------------------------------------------------------- |
| A. 依存（`@banto/*`・`banto-*`） | あり / なし | 対象名・更新元と先のタグ・追従が要る API／型                          |
| B. コピーしたテンプレート        | あり / なし | 対象ファイル・ルート・関連 PR・手で取り込む変更・調整が要りそうな箇所 |
| C. DB・設定・配布資産            | あり / なし | 移行の要否・順序・バックアップ・戻せる条件                            |

### A. 共通パッケージ・クレート

- 対象: `@banto/…`（変更あり）、他は版数のみ。
- 更新: `vA.B.C` → `vX.Y.Z`（npm と Rust を同じタグに）。
- 追従: 削除・改名した API と移行先（表）。型エラーの典型と直し方。`AuthProvider` のように契約が変わる型は、
  必須になったメンバーを明記する。
- 依存を上げずに留まれるか: できる / できない（理由）。

### B. コピーしたテンプレート

- 対象ファイル・ルート: パスを列挙（`apps/admin-template/...`）。
- 関連 PR・コミット: `#NNN`（同期記録に写せるよう、取り込み単位で番号を付ける）。
- 手で取り込む変更: 何をどう置き換えるか（手順は番号付き）。
- 派生側の独自変更と衝突しやすい箇所: 例「設定画面に項目を足している場合は…」。
- 取り込まなくても動くか: 動く / 動かない（A と組み合わせたときの条件）。
- 手本にできる admin-template のファイル。

### C. DB・設定・配布資産

- マイグレーション: 要 / 不要。要なら番号と方言（sqlite・postgres）。適用は起動時に自動。
- 戻せる条件: 新版を本番 DB で最初に起動するまで（以降はバックアップの復元）。バックアップの取り方の指定。
- 設定キー・`tauri.conf.json`・配布物: 変更点と順序。
- 順序: 例「A・B を先に完成 → 検証用 DB で起動 → 本番」。

### 更新後の確認（この版に関係する範囲）

1. `pnpm check` / `pnpm build` / `pnpm dev`（画面が描画される）。
2. この版の変更に関係する操作（具体的に。例: 「各設定カテゴリの保存」）。
3. Rust: `cargo check` / `cargo test`。

### セキュリティ

- なし／あり。ありなら: 影響する利用形態（LAN 公開・Tauri のみ・PostgreSQL など）、修正が A か B か
  （B なら**コピー側の取り込みが必要**と明記）、推奨対応と期限。

### 検証した組み合わせ

- Node.js / pnpm / Svelte / SvelteKit / Vite / Rust のバージョン（[upgrading.md 8.3](upgrading.md#83-候補-commitリリースタグの検証手順手動)）。
- 外部利用（Git 依存 + dev 起動）の検証結果: 実施した ref と成否。
```

## 判断の目安（書く前に確認する）

- `packages/`・`crates/` の**実装が 1 行でも変わったか** → A は「あり」。公開 API の変更なら破壊的かを
  [publishing.md](publishing.md)「バージョニング規約」で判定する。
- `apps/admin-template/`（`src`・`core`・`src-tauri`・`messages`・`e2e`）や `scripts/` のコピー対象が変わったか
  → B は「あり」。A だけの版でも、**コピー側が呼ぶ API が変わる**なら B も「あり」。
- マイグレーション・設定キー・CSP・同梱ファイルが変わったか → C は「あり」。
- 修正が `packages/`・`crates/` にあるか、`apps/admin-template/` にあるか → セキュリティ修正の経路（A / B）。
- 共通 UI をパッケージ化した版（#220）は、**コピー済みファイルの削除と import の置き換え**を B の項目に書く
  （[upgrading.md 9 節](upgrading.md#9-共通-ui-のパッケージ化220への適用)）。
