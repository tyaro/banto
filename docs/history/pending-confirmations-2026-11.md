## B. まとめて了承（既定どおりで困らない。推奨はすべて「了承」）

### #664 HeaderNav の `kind:'menu'`

- メニュー項目は「その他」に移さず上段に固定。
- 置き場は `entries` の並びどおり。メニューのボタンには未読の点・アクティブ表示を出さない。
- `title`（無効の理由）は action / checkbox に通した。radio は未対応（要るときに足す）。

### #665 dock-svelte の pane 一覧・表示の口

- `panels` の並び＝id を初めて見た順（定義順にしたいアプリは並べ替える）。
- `placement` は隠した docked pane も `'docked'`（戻る先の見込み）。
- `close: false` の pane は `setPanelVisible(false)` でも外さない（`refused`）、メニューでは無効のチェック。
- 唯一の docked pane を隠した後に別の pane がドックされていたら、浮動で開く。
- 復帰時の割合は 5〜95% に丸め、他の pane は比例で縮める。

### #667 「表示」メニュー（admin-template）

- バーの置き場は管理ナビの後ろ。主ナビとは別の HeaderNav（←→ でつながらない）。
- 見出しの並びは「表示」→ 注釈。landmark 名「ページのメニュー」。
- layout に無い pane（SPC・トレンド）は浮動で足す。閲覧者にもメニューを出す。

### #672 ピン

- 浮動ウィンドウ単位（ドック中には出さない）。固定中もタブの出し入れ・閉じる・別ウィンドウ・前面化は可。clamp は効く。
- `pinned` は true のときだけ書き出す、`version` は 2 のまま。ボタンは常に出す（消す口なし）。
- API は `DockState.isPinned` / `setPinned` のみ（`DockHost` に口なし）。アイコン 📌。
- ドックに合流すると pinned は消える。ドラッグ・リサイズ中に固定されたら cancel。

### #673 浮動ウィンドウの折りたたみ

- `collapsed?: boolean`（true のみ書き出し）、保存の高さは変えない。口は `DockState` のみ。
- 畳み中は本体を `hidden`+`inert` で残す。`beforePanelChange` は聞かない。ピンとは独立。
- clamp は保存の高さで考える。ドックに合流で collapsed は消える。
- 畳み中は中のタブを外へドラッグできない（許容）。

### #674 ドック中の区画の折りたたみ

- ラベル `collapsePane` / `expandPane` を新設。
- 全部畳まれた split は全部展開。1 枚に縮んだ tabs の collapsed は panel に引き継ぐ。
- 中心ドロップ・タブ追加で展開。帯からのドラッグ不可、帯の上のドロップは無視（`data-dock-no-drop`）。
- 無効の divider は `tabindex=-1`+`aria-disabled`。tabs の見出しを `tab-header` に。
- `structureKey` に collapsed を入れない。▾ は常に出る（単独区画では disabled）。
- 狭い幅で見出しの題名が省略される（「月別更…」）— 許容。

### #681 押し出される pane への確認

- move-docked で元の分割が縮む側も聞く。

### #683 抜く経路の確認

- 順序は残る側が先・抜かれる pane が最後、1 つでも拒否なら何もしない。
- 作り直されないケースは聞かない。`keepMounted` も聞く。新しい reason は足していない。
- フォーカスの移し先は既存のまま。
