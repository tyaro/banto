# レシピ: ログイン無しの小さなアプリ（チョイアプリ）として始める

作成日: 2026-09-01（choiapp-feedback-2026-09 §5 から切り出し。トラックB＝
アプリ作者向け）

担当者数人・単機能の小さなアプリでは、毎回のログインが一番のノイズになる。
Banto は **M11 ログイン不要モード**でこれに対応している: ログイン画面なしで
使い始めて、アプリが育ったら（複数人・ロール分離・LAN 配信が要るように
なったら）通常のログイン運用へ切り替えられる。

## ログイン無しで始める

1. テンプレートをコピー・リネームし、デスクトップアプリ（Tauri）として起動する。
2. それだけでよい。**新しい DB は、アカウントなし・ログインなしで起動する**
   （v8.0.0 から。初回セットアップの画面は無い）。そのままダッシュボードに入り、
   以後もログイン画面なしで起動する（起動時ロールは `admin`。
   「設定 → セキュリティ」で変更できる）。

ログイン必須で使っているアプリでも、**設定 → セキュリティ →
認証を無効化** を ON にすれば同じ状態になる（この場合アカウントは残るが、
ログインなしの間はそのアカウントでログインできない）。

制約（いずれも仕様 M11 の意図的な護り）:

- **操作できるのはデスクトップ（Tauri）のウィンドウだけ。** ログイン不要モード中は、
  LAN アクセスを（閲覧公開なしでは）有効化できない。閲覧公開つきで有効化しても、
  LAN の端末は読むだけで、ログインも書き込みもできない（下の「表示専用アプリ」）。
- 端末を開ける人は誰でも操作できる。**完全に信頼できる端末でのみ**使うこと。
- 監査ログには、組み込みのユーザー `admin` の操作として残る（`actorKind` は `local`）。
- ヘッドレス（`banto-serve` だけ）では、この形では使えない: ログインなしで閲覧公開も
  off の DB では、`banto-serve` は待ち受けずに止まる（下の「ヘッドレスの最初の管理者」）。

さらに手早くしたい場合は `pnpm scaffold --preset minimal` でオプション資産
（dock/charts/添付/帳票など）をまとめて外せる（[remove-optional-assets.md](remove-optional-assets.md)）。

## 育ったらログイン機能を足す

1. **ユーザー管理**で、管理者（`admin` ロール）のアカウントを 1 つ作る。
   ログイン必須へ切り替えるには、ログインできる管理者のアカウントが要る
   （無いと、設定のスイッチは切り替えられず、理由とユーザー管理への導線が出る。
   保存を直接呼んでも断られる）。`admin` という名前は組み込みのユーザーのものなので、
   別の名前にする。
2. **設定 → セキュリティ → 認証を無効化** を OFF にして保存（この操作は
   ログイン不要モード中なら合成セッションのロールに関係なく実行できる —
   キオスク的に `viewer` で運用していても戻せる escape hatch。ただしその場合、
   手順 1 のアカウントは `admin` ロールの間に作っておく）。
   保存した時点でログイン画面に戻るので、手順 1 のアカウントでログインする。
3. ユーザー管理画面でメンバーのアカウントを追加する（ロールの増やし方は
   [add-role.md](add-role.md)）。必要なら **設定 → サーバ・接続 →
   LANアクセス**を有効化して LAN 配信へ（[lan-access.md](lan-access.md) のセキュリティ注意を
   必ず読むこと）。

毎回のパスワード入力だけを省きたい（がアカウントは残したい）中間形態には
**自動ログイン**（設定 → アカウント → 自動ログイン。資格情報は OS キーリング
保存）もある。

## 表示専用アプリ: 書き込みはデスクトップ 1 台、閲覧は LAN の端末がログイン無し

アンドン・常設ダッシュボード・展示デモのように「操作する端末は 1 台、あとは
タブレットや壁のモニターが眺めるだけ」の形は、上記のログイン不要モードに
**閲覧公開**（Issue #189、[ADR-0012](../adr/0012-lan-public-viewer-synthetic-session.md)）を
重ねる。

1. デスクトップ（Tauri）をログイン不要モードで使う（新しい DB はそのまま。
   ログイン必須にしていたら「設定 → セキュリティ → 認証を無効化」。
   書き込みはこの端末だけ）。
2. **設定 → サーバ・接続** で「ログイン無しで LAN から閲覧を許可する
   （閲覧公開）」を ON にし、続けて LAN アクセスを ON にして「保存して適用」。
   閲覧公開が OFF のままだと LAN アクセスは有効化できない（M11 の排他は
   閲覧公開 ON のときだけ緩む）。
3. 表示された URL / QR コードを閲覧端末のブラウザで開く。ログイン画面を経ずに
   `viewer` ロールの合成セッション（ユーザー名 `public`）でダッシュボードに入る。

閲覧端末に見せる画面は `src/lib/navigation.ts` の `publicViewer: true`
（既定: dashboard と items）で絞る。自分の監視画面を足したらその nav item に
`publicViewer: true` を付ける。閲覧端末のテーマやドックのレイアウトは
`public` 名前空間で**全端末共有**になる（壁のモニターが同じ見た目になる）。

制約: 閲覧公開は「LAN 上の誰でも `viewer` として読める」設定であり、
書き込みは合成セッションからは常に 403（例外は、閲覧端末の自分の表示設定だけ）。
**ログイン不要モードの間は、閲覧端末からログインできない**（アカウントがあっても断られる。
LAN から業務・管理のデータを変えられないことが、このモードの安全の前提）。
閲覧端末で編集したくなったら、まずデスクトップで管理者のアカウントを作って
ログイン運用に切り替える（上の「育ったらログイン機能を足す」）。その後は、
ヘッダの「ログイン」から通常アカウントでログインできる。

## ヘッドレスの最初の管理者（`banto-serve create-admin`）

`banto-serve` だけで動かす（PostgreSQL の運用・デスクトップの無いサーバー）ときは、
デスクトップのログインなしのセッションが無いので、最初の管理者をコマンドで作る。

```sh
# サーバーを止めた状態で。パスワードは標準入力の 1 行目（引数には書かない）。
BANTO_DB=./app.sqlite3 banto-serve create-admin --username owner --display-name "管理者" < password.txt
```

- **管理者の作成と、ログイン必須への切り替えを 1 度に行う**（1 つのトランザクション。
  失敗したら、アカウントも認証の設定も監査も残らない。新しい DB では migration だけは適用される）。待ち受けは始めずに終了する（終了コード 0 = 成功、1 = 失敗、2 = 引数の誤り）。業務データのサンプルは入れない（それは起動のとき）。
- 新しい DB をそのまま `banto-serve` で起動すると、「ログインなしで閲覧公開も無効」なので
  待ち受けずに止まり、このコマンドを案内する。最初の起動を飛ばして、新しい DB に直接使ってもよい
  （初回起動の既定設定もこのとき入る。`display` プリセットの閲覧公開は有効のまま残る）。
- **アプリとサーバーを止めてから**実行する（動いているプロセスのセッションは、コマンドからは切れない）。
- パスワードは、**端末（TTY）から実行すると非表示で 2 回**（入力と確認）聞かれる。2 回が一致しなければ DB に触れずに終了コード 1 で終わる。パイプ・ファイルのリダイレクトのときは、今までどおり標準入力の 1 行目をそのまま使う（確認なし。CI・スクリプト向け）。
  - 手動確認の手順（TTY の経路は自動試験に載らない）: 端末で `BANTO_DB=./tmp.sqlite3 banto-serve create-admin --username owner` を実行 → ①入力が画面に出ない ②一致する 2 回で成功する ③一致しない 2 回で「2 回の入力が一致しません」と出て DB が作られない ④終了後の端末でエコーが戻っている（打った文字が見える）。Windows（PowerShell・コマンドプロンプト）と Linux/macOS の端末で行う。入力中に Ctrl-C で止めると Unix の端末はエコーが切れたままのことがある（`stty echo` か `reset` で戻る）。
- 予約されたリストア（`restore-pending.sqlite3`）があるときは、DB に触れずに止まる。
  先にリストアを適用する（一度起動する）か、そのファイルを消してから、もう一度実行する。
- **起動が止まった DB の復旧**にも同じコマンドを使う: `auth.disabled` の行が無い・読めない、
  ログイン必須なのに管理者のアカウントが 0、のどちらも、管理者を作ってログイン必須に書き直す。
  デスクトップの DB（SQLite のファイル）にも、同じファイルを `BANTO_DB` で指して使える
  （そのアプリもログイン必須になる）。
- 監査ログには、組み込みのユーザー `admin` の操作として残る（`actorKind` は `cli`）。
